AI 离线翻译插件 · 分享包说明
================================

适用工具集：STALKER Localization Toolkit 1.1.0（六个图形化栏目那个 Hub）
插件版本：ai_translate 1.9.0


一、怎么装（30 秒）
-------------------
把本压缩包里的 plugins 文件夹，整个覆盖到工具集目录下（与
"STALKER Localization Toolkit 1.1.0.exe" 同级），最终结构应为：

    STALKER Localization Toolkit 1.1.0\
        STALKER Localization Toolkit 1.1.0.exe
        plugins\
            ai_translate.py
            ai_translate_assets\
                xray_pkg.zip
                stalker_termbase.json
                glossary_builtin.json

重启工具集，顶部会多出一个「AI 翻译」栏目（都在同一个窗口里）。
装到 Program Files 等只读位置也能用：插件会自动把模型、运行库、
配置改存到 %LOCALAPPDATA%\STALKER Localization Toolkit\ai_translate。

二、包里有什么 / 没有什么
--------------------------
本包只带「插件代码 + 必需解析器 + 术语数据」：

    ai_translate.py                      插件本体，纯 Python 标准库
    ai_translate_assets\xray_pkg.zip     解析 X-Ray 文本 XML/LTX/脚本所必需
    ai_translate_assets\stalker_termbase.json   术语基表（分类格式，导入用）
    ai_translate_assets\glossary_builtin.json   随包术语库（8855 条，只读）
    ai_translate_assets\THIRD_PARTY_NOTICES.txt 第三方来源与许可状态（必读）
                                                  用户自己的增删改记在 glossary_user.json（不随包）

以下**都不随包**，因为插件可以自己下，而且换机器、换网络时反而是负担：

    bin\        显卡/CPU 运行库（CPU≈19MB；CUDA 12.4≈630MB；CUDA 13.4≈580MB）
    models\     离线模型（Hy-MT2 7B 约 4.4 GB / 1.8B 约 1.8 GB）
    config.json 档位、后端、目录等设置（首次运行按默认值自动生成）
    logs\ downloads\   运行日志与下载缓存

好处：包小（约 0.8 MB）、可放任意位置、在任何人的机器上首次运行都会按**他自己**
的硬件与网络重新选档和测速选源，不会继承别人的设置。
本包内不含任何绝对路径、用户名或本机设置项，已由自动化测试逐项核对。

`ai_translate.py` 当前 6941 行（开发注释已大幅精简，保留必要的安全说明；
函数与类文档字符串保留）。本版新增的官方 SHA-256 校验已通过 251 项回归测试
和定向篡改测试（正确哈希通过、错误哈希删除并拒绝）。


三、首次使用（五步，界面里按 ①→⑤）
----------------------------------
① 硬件检测   点一下，自动识别显卡并推荐后端 + 模型档
② 运行环境   选后端（默认 CUDA 12.4；新驱动可选 CUDA 13.4）
              → 点「测速选源」→「下载运行库」（自动实测各镜像速度并挑最快）
③ 离线模型   选一档（精雕 7B / 精准 1.8B / 神速 1.5 1.8B / 自选任意 GGUF）
              → 点「测速选源」→「下载模型」
④ 启动引擎   点「启动引擎」（首次加载较慢；完成后会做一次启动自检）
⑤ 翻译       选待翻译目录 → 「扫描选档」→「开始翻译」

   ⑤ 里的「引用层」选项（默认值已按“不漏文件、不瞎改”设好）：
     * 识别 ID 引用层（开）：XML/脚本只写条目 ID 的 MOD（如
       <text>some_id</text>、game.translate_string("some_id")）会自动解析，
       翻译定义该 ID 的 configs/text 文本表；引用文件不改写。
     * 输出完整补丁（开）：文本表 + 引用层 XML/脚本 + configs 顶层 ltx
       原样带入输出；字体资源（dds/ini）按约定不处理。
     * 只译被引用条目（关）：默认所有非中文文本表条目都译；想保守时勾选。
     * 保护专名/歌名/型号（开）：Artist:Title、武器型号、演职员表、调试串
       等保留原文；关闭后这些也会送翻。
     * 先预览（关）：只扫描并写日志，不落盘；确认后再取消勾选执行。
   输出目录里的「待确认_未解析引用.csv」不是游戏文件，只用于人工核对
   （引擎动态生成的 ID 等）；部署时不要复制它和 .ai_translate_done.json。

网络：内置直连 + 22 个 GitHub 公共镜像 + ModelScope/HuggingFace 双渠道（含 hf-mirror.com / hf-mirror.net），
自动实测速度、失败换源、断点续传；只有点「下载」才会联网，翻译全程本地推理。


四、模型提示（重要）
--------------------
三档内置模型（7B / 1.8B MT2 / 1.8B MT1.5）的官方文件均已实测确认**内置对话模板**，
可直接接受系统提示词与术语约束（见 §五）。
请使用**官方发布、内置对话模板**的 GGUF。用第三方魔改或转出来的 GGUF 可能
缺 tokenizer.chat_template，表现为"一句短句也生成不停、最后超时"。
本版会提前告诉你：
  * 启动引擎时读 GGUF 元数据，缺对话模板会直接告警；
  * 引擎就绪后自动跑一条 16 token 的自检；若是推理型模型（预算耗在思考上），
    会用 256 token 复核；仍不收尾才告警 tokenizer/对话模板问题。
看到告警请换模型，不要硬跑（否则每条文本都会超时）。

五、术语库（已随包附带）
------------------------
包内已附带两份术语数据（8855 条），都可用界面上的「导入JSON」加载：

    stalker_termbase.json   分类格式：{"分类名": {"原文": "译文"}}
    glossary_builtin.json   扁平格式：{"原文": "译文"}（上面那份展开后的结果）

术语分两层，升级不会丢你自己的词条：
  · glossary_builtin.json = 随包只读层，新版本会整体替换（正常术语更新）；
  · glossary_user.json    = 用户层，你在界面里新增/删除/清空的差异写在这里，
                            升级覆盖 plugins/ 时不会被动到。
  旧版把两者放在同一个文件里（assets/glossary_user.json），升级会把自定义
  词条一起冲掉；本版首次加载会自动把它识别为「与内置的差异」并迁移。

「强制术语」勾上后，命中的术语会无条件替换成你指定的译名，保证专名前后一致。
两种格式可以混在一张表里导入（3 合 1 都支持）。要换成自己的表：
「导入JSON」按同名词条以导入文件为准合并；「导出JSON」可导出当前术语库备份。

v2 分层说明（随包库，不需要你手工维护）：

    canon       阵营/地点/变异体/物品 1377 条，强制+提示
    names       人物与军衔 3068 条，只做整条精确/首字母大写软提示
    technical   单位/缩写 18 条，只做整条精确
    reference   ANTHOLOGY 参考 148 条，只做软参考

「重复句精确复用（TM-lite）」默认勾选：同一批文本里完全相同的句子达到
20% 且不少于 40 条时才启用，只复用本次任务已经译好的同源译文；不联网、
不建跨 MOD 持久库。NS7 实测全局重复率 7.4%，只有 5/182 张高重复表触发。

实测（1.8B 与 7B 各跑 A/B）：术语这类“点状约束”用提示词也能纠正
（1.8B 基线把 артефакт 译成“道具”，注入术语提示后改为“神器”）；
但**长度、格式这类硬指标靠提示词守不住**——实测两档模型都无法稳定满足
“不超过 N 字”这类要求。所以：必须强制的译名请写进术语库（「强制术语」是
确定性字符串替换，不依赖模型配合）；提示词只当作“软引导”。

### 词库到底提升多少（10 条原文 × 三模式实测，两档模型结论一致）

| 模式 | 术语准确率 | 句子流畅度 | 上下文成本 |
|---|---|---|---|
| 不用词库 | **27.8%**（5/18） | 好 | 0 |
| 参考注入（软提示） | **100%**（18/18） | 好 | 约 +60~100 字符/条 |
| 强制替换（默认） | **100%**（18/18） | 好（v1.5.0 已修） | **0** |

术语准确率判据：原文出现的术语，译文是否用了词库指定的中文写法。
典型差距：Сидорович 不给词库时译成“西多罗维奇”，词库指定“西德洛维奇”；
Зона 不给词库时译成“安全区/区域”，词库指定“禁区”。

**v1.5.0 修掉了强制替换的“拼接感”**：旧做法把术语之间的每一段各自送翻
（一句话 3 个术语＝4 次请求），片段之间没有上下文，译文会碎、标点被打散，
例如「去那儿吧。西德洛维奇拿去吧。战利品然后呢——神器然后就进安全区去。」
新做法先把术语换成占位符、**整句翻一次**、再回填词库指定译名：
「去西德洛维奇那儿，拿上战利品，然后再拿神器，接着就进安全区。」
同一批 10 条原文实测：句段数 26 → 14（越少越不碎），术语准确率仍 100%。
占位符若被模型改动，会自动回退旧做法，不会产出坏译文。

**结论与建议**：
* 想提升**译名一致性**：词库是唯一有效手段（27.8% → 100%）。
* 词库**不提升**通用语言质量，也**不占**上下文（默认模式 0 成本）。
* 默认的「强制术语」现在是“术语 100% 确定 + 整句通顺 + 零上下文成本”，
  建议保持勾选。取消勾选（参考注入）术语同样 100%，但每条请求会多带
  一小段术语提示（约 60~100 字符），没有额外收益时不必关。
* 本版已补录一批高频地名/简称（共 38 条，见 `术语库_处理记录.md`）：
  Бар/Бару→酒吧、Болото→沼泽、Мёртвое озеро→死湖、Рыжий лес→红森林、
  Четвёртый энергоблок→四号反应堆、Военные/Армейские склады→军用仓库、
  Зона отчуждения→隔离区、**Зона 的 6 种格变化→禁区**、Псевдопёс→伪犬、
  Пси-собака→灵能犬、Электрохимера(s)→电击奇美拉、ПДА/КПК→PDA（**保持原文缩写不译**）、
  Бинты→绷带、Настройки→设置（一律沿用词库既有风格：Кордон→封锁线、
  Бармен→酒保、Пси-собаки→灵能犬）。
  缩写口径：**PDA 保持原文不译**（原文 `PDA` / `КПК` / `ПДА` 一律输出 `PDA`；
  `PDA Signal`→`PDA信号`）。
  实测效果：`Иди к Бару…` 由原来的“巴鲁”改为“**去酒吧那儿**”。
* 词库剩余的主要缺口是**格变化**（俄语名词变格）：词库现有约 21% 条目是变格
  形式，本版把 `Зона` 等最高频名词补齐了，其余仍按主格收录 —— 原文出现
  未收录的格形式时会退回模型自译。发现漏译可直接往词库加该格形式。

### 词库匹配规则（本版）

* **精确大小写优先 + 小写兜底**：词库里 `Сталкер`，原文写 `СТАЛКЕР`
  也能命中（旧版命中不了）；但 `GUARD`→哨兵 / `Guard`→警卫 这种
  “同字母不同译文”的条目**不会被合并**，仍按原文大小写各取各的。
  词库里这类冲突原有 16 组，**已按你的决定统一**：除 `STRELOK`
  （保留“史特列洛克”）外，其余一律采用 B 译名（如 `Guard`→警卫、
  `Options`→设置、`Owl`→猫头鹰、`Unknown`→未知人员、`Zoom`→放大）。
  统一做法是给两种写法**同一个译文**，因此原文写哪种大小写都得到同一译名。
  处理明细见随包 `术语库_处理记录.md`。
* 被当成术语的俄语功能词（и/нет/почти 之类）不会被注入提示；
  本版已从词库中剔除 4 条错译条目（如 Почти“几乎”→曾被译成“邮件”）。
* 术语匹配速度 0.305 ms/条（8 千条词库），比旧版巨型正则快约 100 倍。


六、译文口径（本版新增）与「附加提示词」
----------------------------------------
内置提示词现已明确写入两条口径，**不需要你自己写**：

  1) 粗话保真：脏话、辱骂、俚语、威胁、黑色幽默与残酷描写一律按原文原意
     直译，不得弱化/省略/改写，不得换成书面语或委婉语。
     实测锚例：дерьмо→「屎／狗屎」（不是"糟糕"）、заткнись→「闭嘴」
     （不是"请安静"）、башку оторву→「拧下你的脑袋」（不是"我不会放过你"）。
  2) 地道中文口语：译文要像中国玩家自己说话 —— 用中文语序和短句，禁用翻译腔
     （"我不得不说""就…而言""如此""因此""并且"、生硬被动句、堆"的"）；
     自然使用"啊／吧／嘛／呢／唉／喂"等语气词；并给了一组正反口语对照范例
     （如"我有件事要告诉你" → "我有事找你"）。物品名／按钮／菜单等短标签
     明确要求保持简洁直白、不口语化、不加语气词。

实测（同一批对话样本，原版提示词 → 本版，7B 精雕档）：
    翻译腔标记 3→2，口语词 0→2，平均句长 17.2→16.4
    例：原版"你明白现在发生了什么吗？我们不能再待在这里了。"
        本版"你懂现在发生啥了吗？咱不能再待这儿了。"
短标签副作用检查：5 条物品／菜单标签，0 条被口语化或长度膨胀。

档位建议：**风格类要求由模型能力兑现**。7B 精雕档能听懂并照做（4/4 条样本
输出都随规则改变）；1.8B 两个档位实测基本无视风格指令（4 条样本 3 条逐字节
不变，加范例后略有改善），只适合快速初翻。要"像真人说话"的结果请用精雕档。

「附加提示词」框（可选）：给内置规则覆盖不到的口径用 —— 语气语域、译名风格、
世界观补充说明等。点「填入示例」会写入四行模板供你删改。注意它是**软引导**
（模型多半遵守、但不保证）；必须强制的译名请写进术语库，「强制术语」是确定性
字符串替换，不依赖模型配合。留空即只用内置规则。


七、已知限制
------------
* ltx 只翻译 description* / inv_name* / title / descr 这几类键的取值
  （沿用上游规则），其它行的值不会被提取。
* 编码判定为"UTF-8 优先，其次按 XML 声明，再 cp1251 → cp1252"。
  无 BOM、无声明、且同时是合法 cp1251/cp1252 的西文文件请把「源语言」
  选成 eng，或在文件头补 XML 声明。
* 目录选择框目前依赖 Tk 后端；Qt 试点后端下请把文件夹直接拖进输入框。
* 翻译大量小文件时，界面只显示每 50 个文件一条进度；逐文件明细在
  logs
untime_*.log 里（这也是排查问题的首选文件）。
* 镜像可用性随网络与时间变化：同一个源在不同地区/运营商下可能时通时不通。
  插件每次下载前都会逐个测速，标「不可达」的源不会被自动选用（手动在
  「源」下拉框指定时仍会先试它）；原有源全部保留，作为不同网络下的备援。
* CUDA 13.4 的可用性判断只是门槛估算（驱动 ≥ 580、计算能力 ≥ 7.5，
  且需 Windows x64）；OEM/笔记本驱动、Optimus、UMD 与 Toolkit 版本差异都
  可能让它实际起不来。插件用真实启动 + GPU 层验证兜底，失败自动回退 12.4。
* 运行库与模型来自 GitHub / HuggingFace 及第三方公共镜像。插件会按发布方
  官方 SHA-256 校验（llama.cpp b11612 Release digest / HuggingFace LFS oid），
  某个源给的文件不一致时会删掉它并**自动换下一个源**；镜像只负责传输。
  仍建议保留原始 zip 自行复核。
* 输出目录里已存在的文件不再无条件跳过：插件会记一份完成账本
  （输入 size/mtime + 输出 size），输入一变就重译；文本 XML 还会校验输出
  是否覆盖输入的全部 id。这样游戏更新加台词、或上次中断留下半截 ltx，
  重跑都会补上。想强制全部重译，删掉输出目录里的 .ai_translate_done.json 即可。
